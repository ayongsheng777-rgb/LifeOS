| 端点 | 耗时 ms | 评价 |
|---|---|---|
| /api/health | 14-16 | 优 |
| /api/status | 3-15 | 优 |
| /api/todos | 29-32 | 优（含 PG 查询） |
| /api/models | 14-25 | 优 |
| /api/ai/usage | 6-30 | 当前数据量下优 |
| /api/backup/status | 2 | 优 |

## 二、并发能力

**20 并发 GET /api/status：20/20 成功，总耗时 164ms，单次最大 162ms，零错误。** 对个人单用户系统远超需求。

## 三、前端

- dist 总 237KB（JS 210KB + CSS 22KB），加载无压力
- 未做代码分包/懒加载（P3，当前体积下无实际影响）

## 四、AI 性能（实测）

| 项 | 数值 | 说明 |
|---|---|---|
| Agent 对话（"你好"） | 22,984ms | 含意图分类+默认对话两次 LLM 调用，模型侧为主 |
| /api/ai/probe 模型连通 | 9,595ms | z-ai/glm-5.2 实测可达 |
| 客户端并发上限 | Semaphore(3) | 防止突发打满 |
| 故障转移 | 主模型 429/5xx 自动切换备用 | 代码审查确认（client.py L57-76） |
| 缓存 | md5 结果缓存 | 重复提问免调用 |

**优化建议（P3）**：Agent 简单问候也走完整意图分类管线，可对明显闲聊做快路短路（代码已有部分关键词快路）；流式端点 /api/agent/chat/stream 已存在，前端用它可大幅改善体感。

## 五、隐患

| 编号 | 问题 | 等级 |
|---|---|---|
| PERF-1 | ai_usage 无索引 + summary 全表扫描 Python 聚合，数据量增长后统计接口线性变慢 | P2 |
| PERF-2 | 限流/会话全在进程内存，多进程部署会各自计数（当前单进程无影响） | P3 |

## 六、资源占用

- 后端单进程 uvicorn，3 个数据容器（PG/Redis/Qdrant）运行 9h+ 稳定
- 日志扫描：backend.log 0 条 error/traceback；uvicorn.log 全部正常访问记录

**性能评分：85/100**

# 05 数据库报告 — LifeOS V2.0

## 一、数据模型（实测 \d 输出）

| 表 | 关键字段 | 主键 | 索引 | 评价 |
|---|---|---|---|---|
| todos | id/user_id/created_at/title/done/priority/due/done_at | id | ix_todos_user_id | 合理；金额类无语义字段 |
| expenses | id/user_id/created_at/type/amount(numeric 12,2)/category/note/happened_at | id | ix_expenses_user_id | amount 用 numeric ✅ 不用 float，金额安全 |
| personal_facts | id/user_id/created_at/updated_at/category/key/value/source | id | ix_personal_facts_user_id | 设计完整 |
| ai_usage | id/user_id/created_at/model/scenario/input_tokens/output_tokens/cost(numeric 10,6)/latency_ms/ok/error | id | **无 user_id 索引** | 费用 numeric(10,6) 精度合理 |

**优点**：主键/用户索引齐全；金额与费用均用 numeric 定点数，无浮点误差风险；字符长度约束合理。

**不足**：
1. ai_usage 无索引（连 user_id 索引都没有），而 `usage_store.summary` 是**全表扫描后 Python 聚合**（usage_store.py L116-145）——调用量上万后统计接口会明显变慢（P2）
2. 无外键约束（单用户系统可接受）
3. 建表靠 `create_all`，无 Alembic 迁移版本管理（P3）

## 二、数据一致性（实测业务闭环）

| 操作 | 数据库变化 | 一致性 |
|---|---|---|
| 待办创建→完成→查询 | done=false → done=true + done_at 落库 → 回读一致 | ✅ |
| 记账 0.01 元→汇总 | summary 立刻反映 expense=0.01/count=1 | ✅ |
| 删除待办/记账/事实 | 回读均不可见 | ✅ |
| 事实写入 | key/value/category/source 全字段落库 | ✅ |

## 三、数据安全

| 项 | 结论 |
|---|---|
| SQL 注入 | 实测 `' OR '1'='1' --` 注入 facts/expense 查询参数，均正常返回无 500（SQLAlchemy 参数化）✅ |
| 敏感数据 | personal_facts 存个人健康等隐私事实（如用药记录），**明文存储**——单用户自用可接受，但数据库文件即隐私本体，依赖 PG 访问控制与备份加密意识 |
| 连接凭证 | DB_URL 经 env 注入，默认兜底密码 `lifeos_pg_2026` 硬编码在 compose 与 backup.py L30（P2，见安全报告） |
| 端口暴露 | PG 绑定 0.0.0.0:5433（compose 注释为避开本机占用），**局域网可直连**——建议改 127.0.0.1 绑定（P2） |

## 四、缓存与向量库

- Redis：短期记忆 list `lifeos:mem:{uid}`，50 轮/30 天 TTL，异常全吞降级 ✅
- Qdrant：`lifeos_experience` 集合 1024 维（bge-m3），manager.py L78 显式传参；vector_memory.py 默认值 1536 与实际不符，仅作维护隐患记录（P3）

**数据库评分：82/100** —— 模型合理、金额安全、一致性实测通过；扣分在 ai_usage 索引缺失与 PG 端口暴露面。

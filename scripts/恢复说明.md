# LifeOS 灾变备份 — 恢复说明

> 备份由 Windows 计划任务 `LifeOS_Backup_Daily` 每天 03:00 自动执行，
> 存到 `E:\Backups\LifeOS\<时间戳>\`（时间戳形如 `20260817-121801`）。
> 每个目录里有 `manifest.json` 记录本次各组件结果，`E:\Backups\LifeOS\backup.log` 是总日志。

## 一、先看备份在哪、是否成功

```bash
ls E:/Backups/LifeOS/
cat E:/Backups/LifeOS/20260817-121801/manifest.json
```

`manifest.json` 里 `"postgres": "OK (...)"`、`"redis": "OK (...)"` 就是成功；
`"qdrant": "SKIP"` 表示当前 LifeOS 没启用 Qdrant（正常，不是错误）。

---

## 二、恢复 PostgreSQL

备份是 `pg_dump -F c`（自定义格式），用容器里的 `pg_restore` 回灌：

```bash
docker exec -i -e PGPASSWORD=lifeos_pg_2026 lifeos-postgres \
  pg_restore -U lifeos -d lifeos --clean --if-exists --no-owner \
  < "E:/Backups/LifeOS/20260817-121801/lifeos-pg-20260817-121801.dump"
```

说明：
- `--clean --if-exists`：先删同名表/索引再重建，适合「整体回滚」。
- 若只想恢复部分表，去掉 `--clean`，加 `-t 表名`。
- 恢复前最好先停一下后端（`kill` 7208 端口进程），避免写入冲突。

---

## 三、恢复 Redis

Redis 数据是 bind mount（`./redisdata` → 容器内 `/data`），RDB 文件叫 `dump.rdb`。
恢复就是把备份的 `.rdb` 覆盖回去再重启容器：

```bash
# 1) 停 redis 容器
docker stop lifeos-redis

# 2) 用备份覆盖现场 dump.rdb（路径按你实际 bind mount 位置，通常在项目根下 redisdata）
cp "E:/Backups/LifeOS/20260817-121801/lifeos-redis-20260817-121801.rdb" \
   "D:/WorkBuddy/LifeOS/redisdata/dump.rdb"

# 3) 重启
docker start lifeos-redis
```

---

## 四、恢复 Qdrant（仅当以后启用才需要）

```bash
docker exec -i lifeos-qdrant sh -c 'tar xzf - -C /qdrant/storage' \
  < "E:/Backups/LifeOS/<时间戳>/lifeos-qdrant-<时间戳>.tar.gz"
```

---

## 五、日常检查清单

- 每天看 `E:\Backups\LifeOS\backup.log` 有没有 `备份完成` 那一行。
- 备份只保留最近 7 天（可改 `LIFEOS_BACKUP_KEEP` 环境变量）。
- 计划任务「只在用户登录时运行」——如果 03:00 那会儿电脑是**注销**状态（不是锁屏），当天不会跑。人不在但电脑开着的场景，建议保持登录/锁屏而非注销。
- 要改备份时间：Windows「任务计划程序」里找 `LifeOS_Backup_Daily`，改触发时间即可。
